01 / GETTING STARTED

Start with the release status.

A local test ISO has been built. A verified public ISO, installer guide, checksums, and final hardware requirements have not been published here.

Use a separate virtual machine for development tests. Booting a live image and successfully installing it are separate checks.

02 / NETWORKING

Select a mode at login.

Choose Normal for ordinary networking, Tor for supported Tor-routed connections, or Offline to block external networking. To change, fully log out and select again.

I2P is planned and is not currently available as a tested KALQOR mode.

Compare capabilities and limitations →
03 / PACKAGE MANAGEMENT

Keep your packages current.

On a configured KALQOR system:

sudo apt update
sudo apt upgrade

The KALQOR repository is hosted through GitHub Pages. APT verifies signed repository metadata and package hashes. Debian remains the source for base-system and security updates.

Review errors rather than bypassing signature checks. A metadata refresh can leave package versions unchanged.

04 / TRUST

Recognize the archive key.

Archive identity: KALQOR OS Archive

A7D7 8596 5987 1390 C7CB
EEEA AD42 2A07 D0AA E677

Compare the complete fingerprint through a trusted channel before accepting a key. The private signing key is never needed on client machines.

A public key and a fingerprint served together do not independently establish trust. Do not use APT options that disable authentication.

05 / TROUBLESHOOTING

Collect the details that matter.

For a development report, include the build/version, live or installed session, hardware or VM platform, selected mode, and exact steps.

cat /etc/os-release
dpkg-query -W kalqor-branding
systemctl status kalqor-boot-guard --no-pager

Service and helper names differ between the original development VM and the newer ISO. Review logs before sharing: remove personal IP addresses, usernames, tokens, and other sensitive details.
